# 02 设备配对与三端连接

> 目标: 贯通 Mac ↔ Relay Server ↔ iOS 的安全连接、设备配对、在线状态与传输级重连。
> 完成判据: Mac 生成短期配对二维码，iPhone 扫码后与 Mac 绑定；Mac 显示 iPhone 已连接，iPhone 显示 Mac Online，心跳和 WebSocket 断开后可重连。

## 技术设计

- [ ] Server 仅承担 Pairing、Auth、Device Identity、Presence、Routing、Heartbeat、Reconnect 和临时消息缓冲，使用 PostgreSQL 持久化必要的设备与配对数据。
- [ ] Mac 与 iOS 均使用 WSS 主动连接 Relay，通过 device identity 注册后参与路由。
- [ ] Pairing Session 返回 `pairingId`、短期单次 `secret` 和包含 version、server、pairingId、secret 的 QR payload。
- [ ] `secret` 必须短期有效、只能使用一次，成功绑定后立即失效。
- [ ] 设备 token 支持撤销，配对成功后建立 iOS 设备与 Mac 设备的绑定关系。
- [ ] 在线状态同时表达设备与项目可达性，但 Server 不获取项目内容。

## 实现方案

- [ ] Mac 提供连接状态、已配对设备、项目概览与 Pair iPhone 入口。
- [ ] Mac 配对界面展示 QR Code、配对码与失效倒计时，成功后显示已连接设备。
- [ ] iOS 无已配对 Mac 时显示扫码入口，配对后显示 Mac 与项目的在线状态。
- [ ] Relay 使用统一 Envelope 转发已配对设备的消息，通过 ping/pong 维护 presence，并对短暂断线提供临时消息缓冲。

## 开发要点

- Mac 始终向 Relay 建立 outbound connection，不向公网暴露项目或 Agent Runtime 入口。
- Redis 可在后续引入，不作为 MVP 连接闭环的必需依赖。
