# 移动端功能扩展开发计划

## 目标

在 MVP 主链路保持稳定的前提下，继续扩展 iPhone 客户端的上下文组织、变更审查、项目检索、结构化结果和异步提醒能力。开发过程优先复用 iOS Scenario Runtime，让客户端功能在没有真机、Relay、Mac 或真实 Agent 的情况下完成主要闭环；真实设备只承担系统集成和体感验收。

## 开发原则

- iOS 继续只依赖统一协议和共享业务对象，不解析 Claude 或 Codex 原始事件。
- Mac 与 Agent Host 仍是项目文件、Git 状态和完整会话历史的权威来源。
- Relay 不读取项目源码，不执行 Agent；新增服务能力必须保持该边界。
- 默认只读。Git 暂存、提交、回滚，源码编辑和自动修改都不进入本阶段。
- 每个迭代必须同时交付正常场景、失败场景、状态测试和 UI 自动化闭环，不能只完成界面。
- 不为测试修改真实产品行为；测试稳定性通过确定性 fixture、稳定辅助功能标识和可控异步边界解决。

## 统一自动化门槛

每个迭代交付前至少完成适用于该范围的自动化层：

1. 协议或纯状态逻辑的单元测试。
2. 涉及 Agent Host、文件系统或服务端能力时，增加隔离集成测试；文件系统能力使用临时目录或临时 Git 仓库。
3. 涉及远端请求时，Scenario Runtime 覆盖成功、空结果、离线、超时和错误；纯本地能力只提供实际存在的状态场景。
4. 涉及请求/事件接收时，验证 `MobileConnection` 的关联、来源、状态归并和重试；纯 View 状态不制造无意义的网络测试。
5. 至少一条从真实 SwiftUI 入口完成主要用户路径的 UI 自动化。
6. `pnpm check`、`pnpm build`、`pnpm test`、Swift 协议测试、macOS/iOS 构建和 `pnpm test:ios`。

同类边界条件应在自动化层验证，不拆成人工确认项。视觉偏好不阻塞开发交付，积累到版本候选统一检查。

## 集中人工验证范围

版本候选阶段统一检查以下跨功能体验：

- 不同屏幕尺寸、横竖屏和 Dynamic Type 下的布局。
- Session、Files、Viewer、Changes 和 Search 之间的手势体感。
- 大文件、大 diff 和大量搜索结果下的滚动性能。
- VoiceOver、复制粘贴和系统分享菜单。
- 真机网络切换后的请求重试与导航状态保留。

Push Notification 另需验证 APNs 环境、授权弹窗、前后台展示、点击后的深链恢复和 token 轮换。

## 阶段完成条件

05 Push Notification 达到完成判据，且没有扩大到代码编辑、Git 写操作、LSP、调试器、更多客户端平台或云端源码索引时，本阶段完成。MVP 尚未完成的真实连接与安全验收仍由原 MVP 验收计划负责，不与本阶段功能验收互相替代。
