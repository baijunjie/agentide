# 03 项目授权与文件浏览

> 目标: 让 Mac 登记可访问项目，并让 iPhone 在不越出项目根目录的前提下浏览完整文件树。
> 完成判据: 用户可在 Mac 添加项目，iPhone 可看到在线项目、展开和折叠目录，并复制文件或文件夹名称与相对路径；路径遍历和符号链接逃逸均被拒绝。

## 落地状态

- Agent Host 已持久化登记项目并提供本机 HTTP IPC；Mac App 持有唯一 Relay 连接，响应 `project.list` 与 `project.listFiles`，iOS 按需加载并展示目录树。远程项目元数据不包含 Mac 根路径。
- 文件访问通过原生 helper 从项目根目录文件描述符逐段 `openat(O_NOFOLLOW)`，所有符号链接均不可见且不可读；默认忽略目录既不出现在列表，也不能通过直接路径请求。项目变更串行写入，避免并发覆盖。
- 刻意留下的过渡层：Mac App 当前连接开发期固定端点 `127.0.0.1:8788`，Agent Host 仍需作为独立进程启动。里程碑 09 在 MVP 打包验收时负责改为随 App 分发并受监督的 companion process，同时验证 Documents/Desktop 等 TCC 保护目录；代码中已标 `TODO`。
- 已验证全仓 TypeScript 类型检查、构建和 Node 测试，Agent Host 测试覆盖项目并发写入、默认忽略目录、路径遍历、静态与并发符号链接替换、IPC 目录请求；Relay 测试覆盖成功与错误响应转发；Swift 协议测试、macOS 构建和 iOS Simulator 构建通过。未手工操作双端 UI，未在真机完成项目浏览，也未验证打包后的 Agent Host 生命周期与 TCC 授权，这些交给里程碑 09 的 MVP Demo 与安全验收。

## 技术设计

- [x] 复用里程碑 01 的 `Project` 契约，Mac 支持添加目录、删除登记、重命名显示名与检测 Claude Code/Codex 可用性。
- [x] 文件服务提供 list directory、read text file、read binary file 和 list sibling images 的内部能力，本里程碑对外开放 `project.listFiles`。
- [x] 文件树响应复用里程碑 01 的 `FileEntry` 契约。
- [x] 传入路径按项目根目录与标准化相对路径组合，解析后再验证最终路径仍在根目录内。
- [x] 禁止 `../` 路径遍历、绝对路径逃逸和符号链接逃逸。
- [x] MVP 默认忽略 `.git`、`node_modules`、`DerivedData`、`.build` 和 `Pods`，本阶段不开放用户自定义规则。

## 实现方案

- [x] Mac 项目列表展示登记项目与在线状态，提供 Add Project 入口，不修改项目本身。
- [x] iOS 从已配对 Mac 获取 project metadata，进入项目后按需请求子目录。
- [x] File Browser 使用缩进、展开/收起动画和连续路径视觉表达层级，文本、Markdown、图片与不可打开文件都可出现在列表中。
- [x] 文件和文件夹的长按菜单提供 Copy Name 与 Copy Relative Path，便于用户回到 Agent 输入框粘贴。

## 开发要点

- 文件读取权限以 Mac 显式登记的 Project 为唯一边界，iOS 不能传入任意 Mac 路径。
- Server 只路由文件请求与响应，不保存文件树或文件内容。
