# 02 设备配对与三端连接

> 目标: 贯通 Mac ↔ Relay Server ↔ iOS 的安全连接、设备配对、在线状态与传输级重连。
> 完成判据: Mac 生成短期配对二维码，iPhone 扫码后与 Mac 绑定；Mac 显示 iPhone 已连接，iPhone 显示 Mac Online，心跳和 WebSocket 断开后可重连。

## 落地状态

- Relay 已实现 PostgreSQL 设备、配对会话和绑定持久化，以及短期单次配对密钥、按配对关系鉴权的 Envelope 路由、Presence、ping/pong 失联检测、30 秒有界断线缓冲和 token 撤销。生产启动要求 HTTPS `PUBLIC_URL`；仅显式本地开发允许明文 HTTP。
- macOS 可登记本机身份、生成二维码和倒计时、显示连接及已配对设备状态并撤销 iPhone；iOS 可扫描二维码、显示 Mac 在线状态，并在被撤销后退出配对以允许重新绑定。长期 token 按 Relay origin 存入 Keychain。
- 刻意留下的过渡层：项目可达性、Mac 项目概览和 iOS 项目状态由里程碑 03 接入；对应占位处已标 TODO。Agent Host 已具备有界队列和持续退避重连的 Relay Client，但里程碑 03 仍需通过本地 IPC 与 Mac App 统一设备连接和业务消息入口，当前 bootstrap 不启动第二条竞争连接。
- 已验证 TypeScript 全量类型检查与构建、Node 全量测试、Swift 协议测试、macOS 构建和 iOS Simulator 构建；Server 集成测试覆盖身份防接管、单次/过期密钥、Presence、绑定路由、撤销断连和同一 iOS 身份重新配对。未连接真实 PostgreSQL 实例，未在真机验证扫码、网络切换和 WSS 部署。

## 技术设计

- [x] Server 仅承担 Pairing、Auth、Device Identity、Presence、Routing、Heartbeat、Reconnect 和临时消息缓冲，使用 PostgreSQL 持久化必要的设备与配对数据。
- [x] Mac 与 iOS 均使用 WSS 主动连接 Relay，通过 device identity 注册后参与路由。
- [x] Pairing Session 返回 `pairingId`、短期单次 `secret` 和包含 version、server、pairingId、secret 的 QR payload。
- [x] `secret` 必须短期有效、只能使用一次，成功绑定后立即失效。
- [x] 设备 token 支持撤销，配对成功后建立 iOS 设备与 Mac 设备的绑定关系。
- [ ] 在线状态同时表达设备与项目可达性，但 Server 不获取项目内容。设备可达性已完成；项目可达性随里程碑 03 的项目登记与元数据路由一并接入。

## 实现方案

- [ ] Mac 提供连接状态、已配对设备、项目概览与 Pair iPhone 入口。除项目概览外已完成；项目概览随里程碑 03 的项目登记一并接入。
- [x] Mac 配对界面展示 QR Code、配对码与失效倒计时，成功后显示已连接设备。
- [ ] iOS 无已配对 Mac 时显示扫码入口，配对后显示 Mac 与项目的在线状态。Mac 在线状态已完成；项目在线状态随里程碑 03 的项目登记与列表一并接入。
- [x] Relay 使用统一 Envelope 转发已配对设备的消息，通过 ping/pong 维护 presence，并对短暂断线提供临时消息缓冲。

## 开发要点

- Mac 始终向 Relay 建立 outbound connection，不向公网暴露项目或 Agent Runtime 入口。
- Redis 可在后续引入，不作为 MVP 连接闭环的必需依赖。
- Agent Host 已提供可持续重连的 Relay Client，但本里程碑由 Mac App 持有设备连接；里程碑 03 在接入项目登记时补齐 Mac App 与 Agent Host 的本地 IPC，并确定业务消息的单一转发入口。
