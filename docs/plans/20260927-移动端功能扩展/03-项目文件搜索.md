# 03 项目文件搜索

> 目标：让用户在 iPhone 上按文件名快速定位登记项目中的文件，并进入现有 Viewer 或 Context 引用流程。
>
> 完成判据：搜索能在项目边界内返回有限结果，查询被替换或页面离开时能取消 Agent Host 的实际遍历任务；空结果、离线、超时、目录变化和大量结果均具备自动化覆盖。

## 产品范围

- File Browser 顶部增加搜索入口，输入至少两个非空白字符后执行文件名搜索。
- V1 搜索文件名和项目内相对路径，不搜索文件内容。
- 结果显示名称、相对路径和文件类型；目录可作为结果，用于定位并展开对应分支。
- 文本、Markdown 和图片结果复用现有 Viewer；进入 Viewer 后可继续使用 Context 引用。
- 搜索历史只保存在本机且有界，可单项或全部清除；不上传 Relay Server 持久化。
- 新查询替换旧查询，旧响应不得覆盖当前结果，旧遍历任务也必须被协作取消。

## 协议与服务边界

- 增加 `project.searchFiles` 请求/响应，输入只包含项目 ID、不可复用的 `searchId`、查询字符串和固定上限；V1 不提供分页游标，达到上限时提示用户缩小查询。
- 增加 `project.cancelSearch`，引用同一设备发起的 `searchId`。iOS 在防抖查询被替换、离开搜索页或请求超时时发送取消；Mac 把取消映射到对应 IPC 请求，Agent Host 使用 `AbortController` 在目录批次之间协作终止遍历并释放任务登记。
- Agent Host 从已登记项目根目录遍历，复用文件服务的默认忽略集合、无符号链接和项目边界规则。
- V1 不依赖系统安装的 `rg`、Spotlight 或云端索引，保证随包环境行为一致。
- 查询进行 Unicode 大小写不敏感匹配；排序优先文件名开头匹配，其次路径片段匹配，再按路径稳定排序。
- 单次结果数量、遍历文件数量、执行时间和响应字节数均有上限。达到上限时返回 `hasMore`，不把部分结果伪装为完整结果，也不产生可继续使用的分页游标。

## 实现步骤

1. 定义 Search/Cancel DTO、`searchId`、限制与跨语言 fixtures。
2. 在 Agent Host 实现受项目边界约束的文件名搜索和取消机制。
3. 增加 IPC、Mac 转发及 iOS 请求关联。
4. 实现 iOS 搜索状态、输入防抖、结果列表和导航定位。
5. 将结果接入 Viewer、Context 引用和文件树展开恢复。
6. 扩展 Scenario Runtime 的正常、空、达到结果上限（`hasMore`）、取消、错误和超时场景。

## 自动化验收

- 临时目录覆盖大小写、Unicode、重名、深层路径、忽略目录、符号链接和结果上限。
- 快速连续输入只展示最后一次查询，取消或过期响应不污染结果；集成测试确认被替换和离开页面后 Agent Host 的遍历任务实际退出。
- 离线和请求失败保留查询文本并提供重试；项目重新上线后可继续搜索。
- UI 自动化完成：Files → Search → 输入查询 → 打开结果 → Send to Agent → 返回 Session。
- 搜索到目录时可定位并展开；目录已删除时显示可恢复错误并清理无效定位状态。搜索过程中目录变化只影响本次尚未访问的条目，不保证快照一致性，重新搜索取得新状态。

## 不在本轮

- 全文搜索、正则表达式、替换和云端索引。
- LSP Symbol Search、定义跳转和引用查找。
- 搜索 `.git`、依赖目录或项目外内容。
