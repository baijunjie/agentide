# MVP 人工验收清单

> 本文是整个 Mobile Agent IDE MVP 开发计划中人工验证项的唯一执行清单。自动化测试、编译和静态检查不在这里重复；它们通过只是开始人工验收的前提，不代表下列用例已通过。

## 执行约定

每个用例执行后，将标题前的 `[ ]` 改为 `[x]`，并在用例末尾记录：

```text
结果：通过 / 失败 / 阻塞
环境：构建版本或 commit、macOS/iOS 版本、Mac/iPhone 型号、Relay URL
时间：
执行人：
证据：截图、录屏、日志或 CI 链接
备注：失败现象、复现条件或阻塞原因
```

“感觉正常”不算通过。每项必须同时满足其“通过标准”中的全部条件；任一条无法判定时记为“阻塞”，不得勾选。

## 验收环境与样例项目

执行全部用例前准备：

- 一台 macOS 14 或更高版本的 Mac，安装待验收的已签名 Release App，不手工启动 Agent Host。
- 一台 iOS 17 或更高版本的真机，安装与 Mac App 同一构建的 iOS App；模拟器不能代替真机用例。
- 一个客户端可达、证书有效的 HTTPS/WSS Relay，使用真实 PostgreSQL，前置代理已转发 HTTP 和 WebSocket upgrade。
- 验收用 Mac 安装 `jq` 与 `websocat`，并具有只读查询上述 PostgreSQL 验收数据的账号；这些工具只用于观察控制面与凭据生命周期，不替代 App 主流程。
- Mac 上的 Claude 和 Codex 均已完成登录或凭据配置，并允许执行无破坏性的测试任务。
- 为 Claude 和 Codex 分别准备可重复的交互触发条件：将无破坏性测试命令设为需要审批；确认 Claude 当前能使用 `AskUserQuestion`。正式验收前先各触发一次；无法稳定产生指定交互时，相关用例记为阻塞，不用其他 UI 替代。
- 一个专用样例项目，至少包含：
  - 两层以上子目录，以及 `.git`、`node_modules`、`DerivedData`、`.build`、`Pods` 中至少一个应隐藏目录。
  - 内容可事先核对的 Swift、TypeScript、Markdown 文件和一个不支持预览的普通文件。
  - 同一目录中至少两张 PNG 和一张 JPEG，图片内容和文件名能明显区分。
  - 一个项目内符号链接和一个指向项目外的符号链接。
- 样例项目另备一份位于 `Documents` 或 `Desktop` 的副本，用于 TCC 权限验收。

建议先依次执行仓库当前约定的自动化检查：`pnpm check`、`pnpm build`、`pnpm test`、`pnpm check:swift`、`pnpm check:macos`、`pnpm check:ios`。任一失败时，先修复或记录为验收阻塞，不继续执行依赖该能力的人工用例。

## A. 构建、部署与进程边界

### [ ] HV-01 远端 CI 真实触发

**核对目标**

确认基础 CI 不只是本地命令可运行，而是能在仓库的远端 CI 环境中完整执行。

**核对方法**

1. 在待验收 commit 上通过仓库支持的 push、Pull Request 或手工 dispatch 方式触发 CI。
2. 打开本次运行详情，核对 TypeScript 检查与测试、Swift 协议测试、macOS 构建和 iOS 构建均实际执行，没有被条件跳过。
3. 保留指向该 commit 的 CI 运行链接。

**通过标准**

- 全部必需 job 结束为成功，且运行对应的 commit 与待验收版本一致。
- 日志中没有使用缓存后直接跳过核心检查的情况。

**当前阻塞**

仓库当前没有 `.github/workflows/` 或其他 CI 配置，因此本项在建立可触发的远端流程前必须记为“阻塞”。

### [ ] HV-02 已签名 Release App 与随包 companion

**核对目标**

确认 macOS App 可以在不依赖外部 Node、手工 Agent Host 或固定 `127.0.0.1:8788` 的情况下，从已签名发布包启动并监督 Agent Host。

**核对方法**

1. 确认没有手工启动的 Agent Host，然后从 Finder 启动已签名 Release App。
2. 在 Mac App 中切换 `Pairing` 和 `Projects`，添加样例项目，再从 iPhone 请求项目列表。
3. 使用“活动监视器”或进程列表找到 App 启动的 Agent Host PID，执行 `lsof -nP -a -p <PID> -iTCP -sTCP:LISTEN`，记录它的 loopback 监听端口。
4. 用 Codex 启动一个执行 `/bin/sleep 60` 后再输出结果的轮次；确认命令正在运行后正常退出 Mac App，再用进程列表确认 Agent Host 与 Codex 子进程退出。
5. 重开 Mac App，用 Claude 重复步骤 4，确认 Claude 活动 Query 也会在 App 退出时结束；再次重开，确认已登记项目仍存在。
6. 在 Mac App 运行时单独强制结束 Agent Host，观察 App 在退避后自动恢复本地能力。

**通过标准**

- 不另行启动本地 Node 或 Agent Host 也能列出项目并执行 HV-12/HV-13 的真实会话；真实 Relay 与 Agent 凭据仍按验收环境提供。
- Agent Host 仅监听 loopback 且端口不是 `8788`。
- App 退出后无孤儿 Agent Host、Claude 或 Codex 进程；单独结束 Agent Host 后可自动重启并恢复服务。
- 重启后项目、会话元数据和已持久化事件未丢失。

### [ ] HV-03 真实 PostgreSQL 与 HTTPS/WSS 部署

**核对目标**

确认生产形态 Relay 使用真实 PostgreSQL 持久化控制面，客户端对外通信全部使用有效证书保护的 HTTPS/WSS。

**核对方法**

1. 使用真实 `DATABASE_URL` 和 `https://` 开头的 `PUBLIC_URL` 启动 Relay，不设置 `ALLOW_INSECURE_HTTP=1`。
2. 从另一台设备访问 Relay 健康检查，查看证书链、域名和有效期；完成一次配对和双端在线。
3. 核对配对二维码中的 server URL 为 HTTPS，前置代理日志中 WebSocket upgrade 成功，客户端未连接任何公开的 `http://` 或 `ws://` 端点。
4. 重启 Relay 进程但保留 PostgreSQL，重新打开双端并观察原有设备身份和绑定关系。

**通过标准**

- HTTPS 证书校验成功，WSS 能完成连接、Presence 和业务消息路由。
- Relay 重启后原有设备无需重新登记，绑定关系仍然有效；Presence 在客户端重连后重新建立。
- 对外路径不存在明文 HTTP/WebSocket 回退。

## B. 设备配对与连接

### [ ] HV-04 真机扫码、设备身份与在线状态

**核对目标**

确认真机扫码可建立正确的 Mac—iPhone 绑定，两端显示的对端身份和 Presence 一致。

**核对方法**

1. 在 Mac `Pairing` 页点击 `Create Pairing Code`，确认二维码、短码和倒计时出现。
2. iPhone 在 `No Mac paired` 页点击 `Scan Pairing QR`，扫描该二维码。
3. 在 Mac 核对列表中的 iPhone 名称与实机一致，状态为 `Connected`；在 iPhone 核对 `Mac Online` 和项目列表。
4. 正常关闭 iPhone App，等待 Mac 显示 `Offline`；再次打开 App，确认无需重新扫码即恢复在线。

**通过标准**

- 仅扫描一次即完成绑定，Mac 显示正确的 iPhone 名称与连接状态，iPhone 显示 `Mac Online`。
- 两端的 Online/Offline 变化与实际连接一致，重开 iPhone App 后 token 仍可用。

### [ ] HV-05 配对 secret 和 token 生命周期

**核对目标**

确认 pairing secret 短期且只能使用一次，撤销后旧 device token 立即失效，同一 iPhone 可以在撤销后重新配对。

**核对方法**

1. 保存一份新生成的配对二维码截图，用离线 QR 解码工具读取其 JSON 中的 `pairingId` 并记录，再用 iPhone 完成首次配对。截图同时包含 secret，只存放在专用测试环境，用例结束后删除，证据中必须遮挡 secret。
2. 在 Mac 点击 `Revoke`，等 iPhone 回到 `No Mac paired`；将步骤 1 的旧二维码显示在另一屏幕上并再次扫描。
3. 新建另一个配对码并保存截图，等待 Mac 倒计时结束后再扫描。
4. 使用一个新配对载荷和专用设备 ID 创建可丢弃的受控客户端。在临时终端会话中执行以下 zsh 命令，手工输入 QR JSON 中的 `pairingId` 和 secret；输入值不会写入 shell history，返回 token 只保留在当前 shell 变量中。

   ```zsh
   read -r "AGENTIDE_PAIRING_ID?pairingId: "
   read -rs "AGENTIDE_PAIRING_SECRET?secret: "; echo
   AGENTIDE_DEVICE_ID="manual-token-check-$(date +%s)"
   AGENTIDE_CLAIM_RESPONSE=$(jq -n \
     --arg pairingId "$AGENTIDE_PAIRING_ID" \
     --arg secret "$AGENTIDE_PAIRING_SECRET" \
     --arg deviceId "$AGENTIDE_DEVICE_ID" \
     --arg name "Manual token check" \
     '{pairingId:$pairingId,secret:$secret,deviceId:$deviceId,name:$name}' | \
     curl --fail-with-body -sS \
       -H 'Content-Type: application/json' \
       --data-binary @- \
       'https://<relay-origin>/pairing/claim')
   AGENTIDE_DEVICE_TOKEN=$(jq -er '.token' <<<"$AGENTIDE_CLAIM_RESPONSE")
   unset AGENTIDE_PAIRING_SECRET AGENTIDE_CLAIM_RESPONSE
   ```
5. 用支持自定义 Authorization header 和显示 close code 的客户端连接该设备，例如 `websocat -v -H="Authorization: Bearer $AGENTIDE_DEVICE_TOKEN" "wss://<relay-host>/connect?deviceId=$AGENTIDE_DEVICE_ID"`。保持连接，在 Mac 对该受控设备点击 `Revoke`。
6. 核对 WebSocket 客户端收到 close code `4003` 和 `token revoked`；在 PostgreSQL 执行 `SELECT id, revoked_at FROM devices WHERE id = '<device-id>';`，确认 `revoked_at` 已设置，再执行 `SELECT * FROM device_bindings WHERE ios_device_id = '<device-id>';`，确认绑定已删除。
7. 使用步骤 4 保存的旧 token 重新连接同一 WSS URL，确认 WebSocket upgrade 被拒绝；立即执行 `unset AGENTIDE_DEVICE_TOKEN AGENTIDE_DEVICE_ID AGENTIDE_PAIRING_ID`，证据只保留遮挡后的值。
8. 为真实 iPhone 生成新二维码并重新配对。

**通过标准**

- 第二次使用已认领 secret 和使用过期 secret 均失败，不新增或覆盖绑定。
- `Revoke` 使 PostgreSQL 中的 token 记录失效并删除绑定，由 Relay 以 `4003` 主动断开现有 WebSocket，同一旧 token 的新连接被拒绝。
- 新二维码可为同一 iPhone 建立新绑定，两端重新显示在线。

### [ ] HV-06 网络切换与短时断线重连

**核对目标**

确认 iPhone 在 Wi-Fi、蜂窝网络和短时无网络之间切换时会自动重连，并且不丢失或重复可见事件。

**核对方法**

1. 在运行中会话里记下断网前最后一个可见事件，关闭 iPhone Wi-Fi，切换到蜂窝网络。
2. 再开启飞行模式 10–20 秒后关闭，期间保持 Mac 与 Agent 运行。
3. 等待 iPhone 显示 `Mac Online`，返回原会话，比较断网前后的 Activity Feed 和最终结果。
4. 在 Mac 上从 `~/Library/Application Support/AgentIDE/sessions.json` 找到会话 ID，打开 `~/Library/Application Support/AgentIDE/sessions.json.events/<URL 编码后的会话 ID>.jsonl`，记录断网前后的 sequence、类型和可识别内容，逐项对照 Feed。

**通过标准**

- 每次网络变化后都无需重新配对即自动回到 `Mac Online`。
- Activity Feed 按原 sequence 顺序衔接，断网期间的事件最终可见，已有事件不重复，会话最终状态正确。

## C. 项目授权与文件浏览

### [ ] HV-07 Mac 项目管理与 TCC 保护目录

**核对目标**

确认项目只能经 Mac 用户显式登记，新增、重命名和删除登记的 UI 行为正确，且 `Documents`/`Desktop` 等 TCC 保护目录的允许和拒绝路径都不越权。

**核对方法**

1. 在 Mac `Projects` 页点击 `Add Project`，选择普通样例项目；核对默认名称、根路径和 Claude/Codex 可用性。
2. 修改项目名并点击 `Save`，在 iPhone 下拉刷新，核对显示名更新但未暴露 Mac 绝对路径。
3. 点击 `Remove`，确认只删除登记，本机目录和文件仍存在。
4. 在专用测试账户中执行本项。如果该 App 已有 TCC 记录，先退出 App，用 `tccutil reset SystemPolicyDocumentsFolder dev.agentide.mac` 和 `tccutil reset SystemPolicyDesktopFolder dev.agentide.mac` 重置这两项权限，再重开 App；不使用存放个人数据的日常账户执行重置。
5. 添加位于 `Documents` 或 `Desktop` 的样例副本：先在系统权限提示中拒绝，观察 Mac/iPhone 错误；在系统设置中核对当前为拒绝状态，再授权并重试。如果重置后仍未出现提示，本项记为阻塞并保留系统设置截图。

**通过标准**

- 新增、重命名和删除登记都只改变 AgentIDE 状态，不修改项目内容。
- iPhone 只看到显示名、Agent 可用性和在线状态，看不到 Mac 绝对路径。
- TCC 被拒绝时不返回目录内容且有明确失败提示；授权后可正常登记和浏览。

### [ ] HV-08 文件树、路径复制与可见边界

**核对目标**

确认 iPhone 只显示已登记项目内可见文件，目录层级和长按复制结果准确，默认忽略目录和符号链接不可见。

**核对方法**

1. 在 iPhone 打开样例项目的 Files，逐层展开两层以上目录，再收起父目录。
2. 长按一个文件和一个目录，分别执行 `Copy Name` 和 `Copy Relative Path`，粘贴到可编辑文本中与预先记录的值逐字符比较。
3. 查找样例项目中的默认忽略目录、项目内符号链接和指向项目外的符号链接。
4. 打开不支持预览的普通文件所在目录，核对它可识别但不能进入 Viewer。

**通过标准**

- 目录按需展开/收起，层级缩进和名称与 Mac 上的真实目录一致。
- 复制的名称不含父目录，复制的相对路径从项目根开始且不含绝对路径。
- 忽略目录和两种符号链接都不出现；不支持预览的文件不被误当成文本或图片打开。

### [ ] HV-09 文本与 Markdown Viewer

**核对目标**

确认 Swift/TypeScript 源文件与 Markdown 文件显示内容正确，文件信息可复制，返回后文件树上下文不丢失。

**核对方法**

1. 分别打开样例 Swift、TypeScript 和 Markdown 文件，将首行、中间一行和末行与 Mac 原文件比对。
2. 在源文件中纵向和横向滚动，核对行号、等宽字体和长行内容。
3. 在 Markdown 中核对标题、列表、强调和代码等样例内容已渲染，而不是整段显示原始标记。
4. 通过右上角菜单复制文件名和相对路径；返回 Files，核对展开项与滚动位置。

**通过标准**

- 三种文件的内容与源文件一致，无截断、乱序或明显编码错误。
- 源文件可沿两个方向滚动，Markdown 按格式渲染，复制结果准确。
- 返回后仍位于原文件树上下文，已展开目录和滚动位置没有无故重置。

### [ ] HV-10 图片 Viewer

**核对目标**

确认 PNG/JPEG 全屏查看、同目录分页、缩放与返回上下文在真机上正常。

**核对方法**

1. 从 Files 打开一张 PNG，核对全屏图片、文件名和相对路径。
2. 左右滑动，依次核对同目录的另一张 PNG 和 JPEG，不应出现其他目录的图片。
3. 对当前图片执行双指缩放、双击放大/复原和放大后拖动；放大时尝试横向拖动。
4. 关闭 Viewer，核对 Files 的展开项和滚动位置。

**通过标准**

- PNG 和 JPEG 内容与 Mac 原图一致，同目录分页集合正确。
- 1x 状态可左右切图；放大状态优先拖动图片，不误切页；双击可在放大与复原间切换。
- 关闭后返回原目录位置，文件树上下文不丢失。

## D. 真机三层空间与手势

### [ ] HV-11 三层导航、阈值与滚动冲突

**核对目标**

确认 Session → Files → Text File 三层空间在真机横竖屏下都能连续进入和逐级返回，手势阈值、视觉层级、安全区和内容滚动不冲突。

**核对方法**

1. 竖屏从 Agent Session 使用右上角文件夹按钮进入 Files，返回后再从屏幕右侧起手向右拖动进入。
2. 用尺寸叠加层或录屏帧图估算屏宽，从屏幕宽度 68% 以右的位置起手并缓慢水平拖动：小于 15% 屏宽时放手应回弹，超过 35% 时放手应只切换一层。两个距离分别安全位于实现的 24% projected threshold 两侧，避免手指速度导致边界值误判。
3. 进入 Text Viewer，先横向滚动长行源码，再使用右上角独立左拖把手返回 Files；点击左侧保留区域逐级返回 Session。
4. 在 Files 中纵向滚动时尝试层级手势，并从系统返回边缘附近起手，确认无误触、卡死或同时驱动两种导航。
5. 旋转为横屏，重复步骤 1–4；检查刘海/灵动岛、Home Indicator 和左侧返回区域。
6. 分别打开文本和图片再返回，核对 Files 中的展开目录和滚动位置。
7. 对照录屏帧图核对完成态：左侧保留区宽度为屏宽 25% 与 108 pt 中的较小值；Session 退场一层时缩放为约 0.94、左移约 8% 屏宽、模糊约 5 pt、不透明度约 0.78；Files 退到文本层时缩放约 0.95，模糊与不透明度相同。

**通过标准**

- 未越过阈值的拖动连续回弹，越过阈值只切换一层，不跳层或卡在中间状态。
- 退到左侧的层缩放、雾化、位移、透明度、阴影和层叠连续且无闪烁；非活动层不误接收内部交互。
- 完成态的左侧保留宽度和缩放/位移/模糊/不透明度与步骤 7 的目标一致，不因横竖屏切换而越出安全区。
- 竖屏、横屏和安全区下均可见且可返回，内容滚动、图片分页和系统边缘手势不被误触或吞掉。
- 每次返回 Files 都保留原有展开项与滚动位置。

## E. Agent 会话与交互

### [ ] HV-12 随包 Codex 真实会话

**核对目标**

确认从 iPhone 可以通过已签名 Mac App 中的随包 Agent Host 创建、继续和取消真实 Codex 会话，并实时查看归一化事件。

**核对方法**

1. iPhone 打开样例项目，新建 Codex Session，初始任务使用“请列出根目录中的文件，读取 README 标题，不要修改文件；最终回答必须包含一个 Markdown 标题、一个列表和一个行内代码”。
2. 观察 Activity Feed 中的 running 状态、流式文本、工具或命令事件、完整消息和 `turn.completed`；核对最终 Agent 消息已渲染标题、列表和行内代码，不是原样显示 Markdown 符号。
3. 在会话回到 idle 后发送第二条消息，让 Codex 回答前一轮 README 标题，确认上下文连续。
4. 发送“请执行 `/bin/sleep 60`，命令结束后再回答 done”；如出现审批则先批准，确认 Command Block 仍为 running 后点击取消。
5. 确认除一个专用测试会话外，其他 Codex 会话都处于 idle；在该会话再次执行 `/bin/sleep 60`，确认命令运行后，在 Mac 上终止所有 Codex 会话共享的 `codex app-server` 子进程。观察专用会话 Feed 的 Error Block、失败的 `turn.completed` 和最终会话状态；其他 idle Codex 会话如同时出现可恢复的连接错误，也一并记录。

**通过标准**

- 新会话自动出现在列表首位，实际工作目录是登记项目根目录。
- Feed 无需 Terminal UI 即可表达执行过程，流式文本不重复，完整消息可正确替换增量文本。
- 首轮和第二轮都以 `turn.completed` 结束并使 session 回到 idle，第二轮保留上下文；取消产生 cancelled 轮次且只结束当前轮次，之后仍可继续发送。
- Agent Markdown 按格式渲染；强制结束 app-server 后出现可识别的 Error Block 和 failed 轮次，会话回到可继续使用的 idle，不永久卡在 running。

### [ ] HV-13 随包 Claude 真实会话与 Question

**核对目标**

确认 Claude 会话的基本流程与 Codex 一致，并额外验证 Claude 的用户问题能在 iPhone 上回答。

**核对方法**

1. 按 HV-12 步骤 1–4 新建 Claude Session，运行同类的只读任务、Markdown 回答、第二轮追问和 `/bin/sleep 60` 取消。
2. 发送“在继续前必须调用 AskUserQuestion，询问我选择 A 或 B，并允许自由文本；不得自己替我选择”，等待 Question Card。如果当前 Claude 能力未产生 `question.requested`，本用例记为阻塞，不以普通文本问句替代。
3. 选择一个选项并填写自由文本，提交后观察卡片和 Agent 后续输出。

**通过标准**

- Claude 的流式文本、工具、消息、状态和轮次完成以与 Codex 相同的 Feed 形式显示。
- Claude 的 `/bin/sleep 60` 轮次可在运行中取消，产生 cancelled 轮次并回到 idle，之后仍可发送新消息。
- Question Card 的问题、选项和自由文本能力与 Agent 请求一致；提交后卡片立即不可重复提交，Agent 收到正确回答并继续。

### [ ] HV-14 Approval 允许、拒绝与重复提交防护

**核对目标**

确认 Approval Card 只呈现 Agent 实际允许的动作，允许与拒绝都路由到正确会话，并且不会重复提交。

**核对方法**

1. 先按“验收环境与样例项目”的要求，将只读命令 `xcodebuild -list` 配置为在 Codex 和 Claude 中都需要审批；未能产生审批时记为阻塞。
2. 在 Codex 会话请求执行该命令。核对卡片标题、说明、命令和按钮，点击一次 `Approve Once`（若原请求只提供其他允许动作，则点击它实际提供的允许动作）；立即再点击原位置或尝试重复提交。
3. 在同一 Codex 会话发起第二个审批请求并点击 `Reject`。
4. 在 Claude 会话完整重复步骤 2–3，确认 Claude permission 也完成允许和拒绝路径。
5. 在执行步骤 2–4 时同时保留另一个会话，确认审批结果没有路由到其他会话。

**通过标准**

- 卡片不显示原请求未提供的动作；单次允许后 Agent 仅执行一次对应命令并继续当前轮次。
- 提交后卡片立即禁用，没有第二次实际请求；拒绝后命令不执行，Agent 收到拒绝结果。
- 允许和拒绝只影响发起该 interaction 的会话。
- Codex approval 和 Claude permission 的允许、拒绝各至少通过一次；不能用其中一个 Agent 的结果代替另一个。

## F. 恢复与快照

### [ ] HV-15 iOS 进入后台后恢复

**核对目标**

确认 iOS 进入后台导致 Relay 断开后，回到前台会以本地缓存过渡，再用 Mac 快照恢复权威状态和实时订阅。

**核对方法**

1. 在一个持续输出的会话中记录当前最后一个事件、会话状态和 Workspace 所在层级。
2. 将 iOS App 切到后台，期间保持 Mac 与 Agent 运行。等到 Mac 的已配对设备状态显示 `Offline` 或 Relay 日志明确记录该 iPhone WebSocket 断开；如果连接始终未断，本项记为阻塞。
3. 记录断开时会话事件 JSONL 的最后 sequence，再回到 App，观察离线缓存、`Mac Online` 恢复、快照合并和后续实时事件。
4. 按 HV-06 步骤 4 打开该会话的 JSONL，将断开后的 sequence、类型和可识别内容与 Feed 逐项比对。

**通过标准**

- 前台恢复时不需重新配对，原项目、会话和 Workspace 上下文仍可访问。
- 快照与实时流衔接后无事件缺口或重复，状态与 Mac 上实际 Agent 轮次一致。

### [ ] HV-16 iOS 被系统结束后恢复

**核对目标**

确认 iOS App 进程被结束后，最近项目、会话、事件、导航和实时流可从有界缓存与 Mac 快照恢复。

**核对方法**

1. 展开文件树并滚动到可识别位置，进入 Text Viewer；同时让当前 Agent 执行 `/bin/sleep 60` 后再输出结果的任务。
2. 确认 Command Block 仍为 running 后，记录会话 JSONL 当前最后 sequence，再从 App Switcher 强制结束 iOS App；保持 Mac 和 Agent 运行。
3. 在 `/bin/sleep 60` 结束前重新打开 iOS App；如果重开时轮次已终止，重新执行本用例，不把它记为“实时流恢复”。
4. 进入原会话，核对事件、状态、Text Viewer 文件和 Files 的展开/滚动状态；按 HV-06 步骤 4 将恢复后 Feed 与 JSONL 的 sequence、类型和内容逐项对照。

**通过标准**

- 重启 App 后配对、项目与最近会话仍存在，原 Workspace 层级和文件上下文恢复。
- Mac 权威快照覆盖可能过时的本地缓存，事件顺序连续、不重复，并继续接收尚未结束的实时流。

### [ ] HV-17 待处理 Approval/Question 的恢复与路由

**核对目标**

确认 iOS 断线或被结束时，snapshot 中的待审批/待回答交互不丢失，恢复后的回复只到达正确的 Agent session。

**核对方法**

1. 同时保留会话 A 和 B；按 HV-14 已验证的权限策略和命令在 A 中产生 Approval Card，不回应。
2. 在该卡片仍待处理时将 iOS App 切入后台并强制结束，保持 Mac App 和 Agent Host 运行。
3. 重开 iOS App，进入 A，确认卡片仍可响应；批准后观察 A 和 B。
4. 按 HV-13 已验证的 `AskUserQuestion` 任务为 Claude Question Card 重复步骤 1–3，并提交一个选项或自由文本回答。

**通过标准**

- App 恢复后待处理卡片仍属于会话 A，内容、允许动作和已回应状态正确。
- 提交后只有 A 继续运行，B 的事件、状态和交互不变；同一 interaction 不会重复提交。

### [ ] HV-18 Mac/Agent Host 重启后会话恢复

**核对目标**

确认随包 Agent Host 或 Mac App 重启后，已持久化的会话和事件仍然可用，原生 Claude/Codex 会话能在下一轮恢复。

**核对方法**

1. 分别创建一个已完成首轮的 Codex 会话和 Claude 会话，记录各自标题和最后事件。
2. 退出并重开 Mac App；等 iPhone 重新显示 `Mac Online`，刷新会话列表。
3. 进入两个旧会话，发送一条要求引用首轮结果的追问。
4. 另外创建一个正在等待 interaction 的测试会话，重启 Mac App，再尝试回应旧卡片。

**通过标准**

- 已完成会话的元数据和事件历史不丢失，Claude/Codex 都能在同一原生会话上继续下一轮。
- 进程重启时原生待处理请求失效的会话会显式记录可恢复错误并回到 idle；旧交互回复被拒绝，不会误发给新轮次。

## G. 最终 MVP 串联演示

### [ ] HV-19 七组 Demo 连续验收

**核对目标**

在同一个已签名构建、同一对 Mac/iPhone 和同一个样例项目上，不切换到开发服务或临时替身，连续跑通开发大纲规定的全部 Demo。

**核对方法与通过标准**

开始前先恢复干净状态：在 Mac 撤销旧 iPhone 绑定并等待 iPhone 回到 `No Mac paired`；在 Mac 删除样例项目的登记但不删除本机目录；记录本次待验收构建和 commit，确认没有手工 Agent Host 运行。旧会话可保留，但本轮 Demo 2、3 必须创建新会话以与旧证据区分。

1. **Demo 1：连接。** 冷启动 Mac App，添加样例项目，生成配对码并由 iPhone 扫码。通过标准：Mac 显示该 iPhone `Connected`，iPhone 显示 `Mac Online` 和正确项目。
2. **Demo 2：Codex。** 从 iPhone 打开项目，新建 Codex 会话并发送 HV-12 的只读任务。通过标准：Feed 实时出现 Agent 活动，轮次以 outcome `completed` 的 `turn.completed` 结束，session 回到 idle。
3. **Demo 3：Claude Code。** 用同一任务新建 Claude 会话。通过标准：同 Demo 2，且实际执行者为 Claude。
4. **Demo 4：文件浏览。** 从 Session 右滑进入 Files，展开两层目录，长按文件并复制相对路径。通过标准：Session 缩到左侧并雾化，Files 在右侧可操作，粘贴结果与真实相对路径一致。
5. **Demo 5：文本文件。** 分别打开 Swift/TypeScript 与 Markdown 样例，再逐级返回。通过标准：Files 退到左侧并雾化，Viewer 内容正确，返回后原目录上下文保留。
6. **Demo 6：图片。** 打开 PNG，左右切换到同目录 JPEG，关闭 Viewer。通过标准：图片与文件名一致，分页集合正确，返回原目录位置。
7. **Demo 7：Approval。** 复用 HV-14 已验证的 Agent 权限策略和无破坏命令，在 iPhone 点击请求实际提供的允许动作。通过标准：Approval Card 内容正确，批准只提交一次，Agent 执行该命令后继续并完成。

整组只在 7 个 Demo 全部于同一待验收构建中通过时勾选。使用模拟数据、改用手工 Agent Host、临时替换构建，或中断导致设备绑定/项目登记不再连续时，必须从干净状态和 Demo 1 重新开始；仅录屏分段或短暂暂停、且产品状态未改变时，可继续下一 Demo。

## 验收完成条件

MVP 人工验收只在以下条件全部满足时完成：

- HV-01–HV-19 全部勾选，没有“失败”或“阻塞”。
- 所有用例使用同一待验收 commit 产生的构建；如果修复导致 commit 改变，重跑受影响用例和 HV-19。
- 每项都有环境、时间、执行人和可回看证据。
- 最终验收记录中没有以 Simulator、模拟 Agent、内存数据库或手工 Agent Host 替代真机、真实 Agent、PostgreSQL 和随包 companion。
